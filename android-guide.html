IRL Network · Android venue box

Set up the Android venue box.

Everything needed to take a stock YS-M68 display (Rockchip RK3568, Android 11), remove its factory advertising app, install the IRL Player as the Home app, make it the device owner so it updates itself, and hand it over ready to pair. Written for a technician with a Windows PC on the same network. For a plain "put the app on any Android device" walkthrough, use the Android section of the main guide.

2Install ADB on Windows

One zip, no installer.
  1. Download SDK Platform Tools for Windows: developer.android.com/tools/releases/platform-tools
  2. Unzip somewhere simple, e.g. C:\adb (there is no installer).
  3. Open that folder in Explorer, type cmd in the address bar, press Enter. The command window opens already in the right folder.

Optional: add the folder to PATH so adb works from anywhere.

3Enable ADB on the board

Developer options, then USB and network debugging.

On the display:

  1. Settings → About device → tap Build number 7 times.
  2. Go back → Developer options.
  3. Turn on USB debugging.
  4. Turn on network ADB / Wireless debugging if present.
If tapping Build number does nothing, Developer options may already be enabled (check Settings → System), or the firmware has it locked. In that case ask Yisheng how to unlock ADB on the YS-M68 — they usually send a code or a small APK.

4Connect from Windows

Over the network is easiest; USB works too.

Over the network (easiest)

Find the IP in Settings → About device → IP address, then:

adb connect 192.168.1.235:5555
adb devices

You want to see the board listed with the word device next to it.

Over USB

Plug a USB cable into the board's OTG port. If Windows doesn't recognise it, install the Rockchip or Google USB driver. Then adb devices.

Connection errors

MessageFix
unauthorizedTap Allow on the popup shown on the display, tick "always allow"
connection refusedReboot the board, check network ADB is on, confirm the PC is on the same network
device not foundWrong IP, or the board changed IP via DHCP — check Settings again
offlineadb disconnect then adb connect again

5Look at what's installed

List the apps, find the launcher, see what is on screen.

 
adb shell pm list packages           :: everything
adb shell pm list packages -3        :: installed (non-system) apps only
adb shell pm list packages -s        :: system apps only
adb shell pm list packages -d        :: disabled apps
adb shell pm list packages -f        :: with APK file paths

Save the list to a file:

adb shell pm list packages -f > C:\adb\apps.txt

Search inside it (findstr is the Windows version of grep):

adb shell pm list packages | findstr /i "launcher"

Find which app is on screen right now:

adb shell dumpsys window | findstr /i "mCurrentFocus"

Find the current home app:

adb shell cmd shortcut get-default-launcher

On a stock board this returns ComponentInfo{com.softwinner.launcher/com.softwinner.launcher.Launcher}.

6Remove the factory ad app

Disable first (reversible), uninstall for the user if that fails.
Always check it is not the launcher first. If you remove the home app without a replacement, the board boots to a blank screen. ADB still works in that state, so it's recoverable, but avoid it.

Find where it lives:

adb shell pm path com.adviewer
:: package:/odm/bundled_persist-app/captiview3/captiview3.apk

Back it up (optional — install-existing also restores it):

adb pull /odm/bundled_persist-app/captiview3/captiview3.apk C:\adb\

Disable it (reversible, do this first):

adb shell pm disable-user --user 0 com.adviewer

Or remove it for the current user (no root needed):

adb shell pm uninstall --user 0 com.adviewer

Reboot and check:

adb reboot
adb shell dumpsys window | findstr /i "mCurrentFocus"

Restore anything you removed

adb shell cmd package install-existing com.adviewer
adb shell pm enable com.adviewer

A factory reset also brings back every built-in app.

Note: bundled_persist-app means the app is meant to run persistently from boot. If disable-user fails with "cannot disable a protected package", use pm uninstall --user 0 instead — it usually works where disable doesn't.

7Install the IRL Player

Over ADB from the PC, or from a USB stick on the box.

Download the Android build on the Windows PC (the button at the top of this page, or this address):

Install it over ADB:

adb install 
adb install -r      :: reinstall, keeping data

Or copy the APK to a USB stick and open it with the board's file manager (allow "install unknown apps" when asked).

Installing is not the end. Before anything else is set up on the box, make the player its device owner — section 8, one command. Without it the box plays fine but never updates itself.

The package name

Everything below uses the app's package name, which is com.theirlnetwork.player (main activity .MainActivity). It never changes between versions. To confirm it on a board, list the installed apps right after installing, or open the app and ask what is on screen:

adb shell pm list packages -3
adb shell dumpsys window | findstr /i "mCurrentFocus"

Make it the home app

The app declares itself as a launcher, so either:

  • Settings → Apps → Default apps → Home app → pick IRL Player, or
  • press the Home button once and, when Android asks which launcher to use, pick IRL Player and Always, or
  • set it over ADB:
adb shell cmd package set-home-activity com.theirlnetwork.player/.MainActivity

To get back to the box's own menus later, undo the same setting (or set com.softwinner.launcher/.Launcher as the home activity).

Player behaviour checklist

What the app is built to do on this board — check it after the first boot:

  • Keeps the screen on (FLAG_KEEP_SCREEN_ON) so it never sleeps
  • Locks orientation to portrait (the panel is mounted portrait)
  • Hides the status and navigation bars (immersive mode)
  • Uses ExoPlayer / Media3, which picks the RK3568 hardware decoder automatically
  • Restarts playback if a video errors; watches the player position to catch freezes
  • Caches content locally so it keeps playing when the network drops

8Device Owner mode (silent auto-update)

One command per box, before it leaves the bench. Boxes set up with 1.3.1 or older need a factory reset first.
Since version 1.4.0 the app updates itself. Once an hour it reads update.json on this site; when a newer build is listed it downloads it, checks the hash and installs it silently, keeping the pairing and cached media. It can only do that as the box's device owner, which is set once per box with the command below. A box that is not device owner keeps playing the version it has and just logs one line per check — nothing breaks, it simply never updates.

8.1 New box: make the player the device owner

Right after installing the app (step 7) and before anything else is set up on the box:

  1. Settings → Accounts → remove every account. Device owner refuses while one exists.
  2. Run the two commands:
adb shell dpm set-device-owner com.theirlnetwork.player/.IrlDeviceAdminReceiver
adb shell dpm list-owners

list-owners must name com.theirlnetwork.player. Then reboot and confirm the player itself agrees:

adb reboot
adb logcat -d | findstr /i "device owner"      :: expect: [Android] device owner: true
ErrorMeaning
there are already some accounts on the deviceRemove all accounts and retry
device owner is already setAnother app owns it — needs a factory reset
Unable to find componentAn APK older than 1.3.2 is installed — install the current one first

8.2 Existing boxes (set up with 1.3.1 or older)

Device owner has to be set on a fresh box. A box that is already in use cannot be converted in place: factory reset it (Settings → System → Reset), then go through steps 3 to 7 again, set the device owner as above, make the player the Home app and re-pair the screen from the dashboard (the reset forgets the pairing). One last visit per box — after that it never needs a USB stick again.

8.3 How updates roll out

  • The box marked as canary applies a new version within about an hour of it being published.
  • Every other box waits canaryDelayHours (24 today) after it first sees the new version, so a bad build shows up on the canary a day before it reaches the venues. 0 means everyone at once.
  • Only a higher version code is ever installed — a box never downgrades itself.
  • Any failure (offline, missing file, bad hash, refused install) is logged and retried the next hour; playback is never interrupted.

Watch a box's update checks as they happen:

adb logcat -s theirlnetwork.update

The hand controls — forcing a check, marking a box as the canary, rolling back to the previous APK the app keeps on the box — are documented in docs/android-install.md of the irl-player app repository.

8.4 Publishing a new version (release manager)

Put the release's irl-player_<version>_arm64.apk, its .sha1 and the update.json that CI writes next to it into packages/android-arm64/ on this site, and update the download link on both pages. Never hand-write update.json: its versionCode is the arm64 build's code (2000 + the build number — 1.3.1 is 2002, 1.3.2 is 2003, 1.4.0 is 2004) and the boxes only move to a strictly higher one.

Rules that must never be broken: the package name com.theirlnetwork.player and the signing key stay the same forever, and versionCode always increases. Change either and every box rejects the update as a different app.

9Deployment checklist per board

Tick these off on every box before it leaves the bench.
  • Connect over network ADB
  • Disable / remove com.adviewer
  • adb install
  • Remove all accounts Settings → Accounts — device owner refuses while one exists
  • adb shell dpm set-device-owner com.theirlnetwork.player/.IrlDeviceAdminReceiver
  • Verify with adb shell dpm list-owners
  • Reboot; the log says device owner: true
  • Set the IRL Player as the home app
  • Reboot, confirm it starts fullscreen in portrait
  • Confirm video plays smoothly and the screen never sleeps
  • Confirm the update check reaches our server adb logcat -s theirlnetwork.update shows a check with no error
  • Pair the screen from the dashboard with the code on the display
  • Record the board's MAC / serial in our fleet list

10Linux option (parked)

Why the Linux player does not run on this board today, and what to ask the maker for.

The IRL Linux Player cannot run on this board as-is: the installer requires Raspberry Pi OS 64-bit, which does not run on RK3568, and parts of it depend on Pi-only components (raspi-config, the Pi hardware watchdog, Raspberry Pi Connect).

No Linux image for the YS-M68 is published anywhere — Yisheng supplies it on request only. Ask them for:

  • Debian 11/12 or Ubuntu 22.04 image (update.img) for the YS-M68, configured for the QV185FHB-N82 LVDS panel in portrait
  • Hardware video decoding support (Rockchip MPP) and which players support it
  • Linux SDK / BSP and the device tree (DTS)
  • Original Android 11 firmware as a backup, plus RKDevTool and flashing notes
  • For Android: platform signing key and their board API (silent install, reboot, scheduled power on/off, watchdog)

If a Linux image does arrive, porting notes: detect the board with /proc/device-tree/compatible (rockchip,rk3568), hold the vendor kernel with apt-mark hold, use mpv/ffmpeg or GStreamer built with rkmpp for hardware decoding, point systemd's RuntimeWatchdogSec at the RK3568 /dev/watchdog, replace raspi-config audio setup with ALSA/PipeWire defaults, and replace Raspberry Pi Connect with Tailscale + SSH or our own agent.
